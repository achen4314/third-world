# 外部条件获取指南（逐项：去哪拿、填到哪、不给会怎样）

更新时间：2026-11-14 17:30 GMT+8
适用项目：`arc-training`（Supabase 项目 ref `bffuuxdnztowlwbxjlzp`）

这份文档只回答一个问题：**每个卡住的外部条件，具体去哪里点、拿到什么字符串、贴到哪一行。**

优先级从上到下。第 1 项是唯一「给了就能立刻从演示数据变成真实可用」的开关；第 2–3 项决定注册与找回密码是否顺畅；第 4 项起属于上线/合规层面。

---

## 1. Publishable key（唯一硬阻断）

**用途**：浏览器端访问 Supabase 的唯一凭据。没有它，注册、登录、读写全部不成立——只能看演示数据。

**在哪拿（两条路，任选）**

| 路径 | 具体操作 |
|---|---|
| A. 设置页 | 打开 <https://supabase.com/dashboard/project/bffuuxdnztowlwbxjlzp/settings/api> → 顶部 `Project Settings` → `API Keys` → 找 **Publishable key**（形如 `sb_publishable_xxxxxxxx`）→ 右侧复制按钮 |
| B. 连接向导 | 项目页顶栏 **Connect** → 选 **App Frameworks** → 对话框里直接给出 `SUPABASE_URL` + publishable key 的整段代码，整段复制即可 |

> 注意区分：同页还有一个 `service_role` / `Secret key`，**那个绝对不能放前端**。它绕过所有 RLS，一旦进浏览器等于把库交出去。本项目只需要 publishable。

**填到哪（二选一）**

方式一，改文件（长期生效，推荐）：

```js
// prototype/env.js
window.ARC_ENV = {
  SUPABASE_URL: "https://bffuuxdnztowlwbxjlzp.supabase.co",
  SUPABASE_PUBLISHABLE_KEY: "sb_publishable_把这里替换掉",
  ALLOW_RUNTIME_KEY: true
};
```

方式二，不改文件（只对当前浏览器生效）：打开页面 → 右上角「数据源」按钮 → 粘贴到 `Publishable key` → 保存并重连。值存在浏览器 localStorage，换机器要重填。

**填完怎么验证**

1. 页面右上角徽标从「演示数据」变成绿点「真实数据」；
2. 顶部角色选择器变灰（角色改由组织成员关系决定，不再能随手切）；
3. 用 `demo@third.world` / `ArcDemo2026!` 登录，今日页 ACWR 与库里的值一致；
4. 终端跑 `npm run test:api`，会走 PostgREST + GoTrue 全链路（登录 → 读 → 写训练 → 服务端重算 → 清理），9 项全绿。

**不给会怎样**：只能演示模式。所有「真实用户可注册可登录」的验收项都无法成立。

---

## 2. 关闭邮箱确认（注册后立刻能登录）

**用途**：默认开启 `Confirm email` 时，注册成功但登录被拦（提示 email not confirmed），且确认邮件依赖 SMTP——本项目尚未配置 SMTP，所以此刻**必须**关掉它，才能完成「注册即可用」。

**在哪改**：<https://supabase.com/dashboard/project/bffuuxdnztowlwbxjlzp/auth/providers> → `Email` → 展开 → 关闭 **Confirm email** → Save。

**替代方案（不想关确认）**：用 `npm run accounts confirm -- <邮箱>` 手工确认单个账号（脚本直接写 `email_confirmed_at`，绕过邮件）。适合内部试点，不适合真实用户。

**验证**：新邮箱注册 → 不点任何邮件 → 直接登录成功。

**影响面**：只影响注册后的首次登录，不影响已有账号。

---

## 3. SMTP（确认邮件、找回密码真正可用）

**用途**：把 Supabase 默认的发信（有严格频率限制，且发件人是 supabase 域名，容易进垃圾箱）换成自己的发信服务。找回密码功能在真实用户场景下依赖它。

**在哪拿（三选一）**

| 服务 | 拿 API Key 的位置 | 备注 |
|---|---|---|
| Resend | <https://resend.com/api-keys> → Create API Key | 最快，免费额度 3000 封/月；需先验证发信域名（DNS 加 SPF/DKIM） |
| SendGrid | <https://app.sendgrid.com/settings/api_keys> → Create API Key（权限选 Mail Send） | 免费 100 封/天 |
| 阿里云邮件推送 / 腾讯云 SES | 阿里云：<https://dm.console.aliyun.com>；腾讯云：<https://console.cloud.tencent.com/ses> | 境内投递率最好，但**发信域名必须已完成 ICP 备案**，否则不给过 |

**填到哪**：<https://supabase.com/dashboard/project/bffuuxdnztowlwbxjlzp/auth/smtp>（`Project Settings → Authentication → SMTP Settings`）→ 打开 `Enable Custom SMTP`，填 host / port / user / password / sender email / sender name。

**验证**：登录页点「忘记密码」→ 收到邮件 → 点链接改密成功。

**不给会怎样**：找回密码事实上不可用（改密仍可在「数据源 → 账号安全」里用旧密码完成）；确认邮件也发不出。

## 4. Supabase Personal Access Token（部署 Edge Functions）

**用途**：命令行登录 Supabase，部署 Edge Function。目前**导出/删除/注销已经改成数据库 RPC，不再依赖它**；只有以下三件事还离不开：PDF 报告渲染、分享链接签名、第三方 OAuth 回调。

**在哪拿**：<https://supabase.com/dashboard/account/tokens> → `Generate new token` → 起个名字（如 `arc-cli`）→ 复制一次性显示的 `sbp_...`。

**填到哪**：

```bash
cd arc-training
npx supabase login            # 粘贴 sbp_ 开头的 token
npx supabase link --project-ref bffuuxdnztowlwbxjlzp
npx supabase functions deploy <函数名>
```

token 只存在本机 `~/.supabase/access-token`，**不要写进仓库**。

**不给会怎样**：上述三件事做不了，其余功能不受影响。

## 5. 境内服务器 + 域名 + ICP 备案（公开上线的合规硬阻断）

**用途**：面向中国大陆用户公开提供服务，必须满足：境内主体 + 境内服务器 + 已备案域名；做 App 还要做 **App 备案**（工信部，2023 起强制）。

**顺序（这个顺序不能颠倒）**

1. **买域名**：阿里云万网 <https://wanwang.aliyun.com> 或腾讯云 DNSPod <https://console.cloud.tencent.com/domain>。个人可买，实名认证 1–3 天。
2. **买境内服务器**：阿里云 ECS <https://ecs.console.aliyun.com>、腾讯云 CVM。**必须选中国大陆地域**（香港/海外节点不能备案）。最低配 2 核 2G 足够跑反向代理 + 定时任务。
3. **ICP 备案**：买完服务器在对应云厂商的备案系统提交——
   - 阿里云：<https://beian.aliyun.com>
   - 腾讯云：<https://console.cloud.tencent.com/beian>
   需要：主体证件、域名证书、服务器实例（备案服务号）、网站负责人核验（拍照/视频）。**管局审核约 7–20 个工作日**，整体按 3–4 周排。
4. **App 备案**：拿到 ICP 后，在**同一备案系统**里做 App 备案（填 App 名称、包名/Bundle ID、平台、公钥/签名 MD5）。审核约 1–2 个工作日，之后要在 App 内展示备案号。
5. **公安联网备案**：网站/App 上线后 30 日内到 <https://beian.mps.gov.cn> 提交，拿到公安备案号并展示。

**拿到的三样东西分别填到哪**

| 拿到 | 填到哪 |
|---|---|
| 域名 | `prototype/env.js` 的 `SUPABASE_URL` 若改为自建反代，则改这里；DNS 指到境内服务器 |
| ICP 备案号 | App 内「设置 → 关于」页展示，并链接 <https://beian.miit.gov.cn>（本项目 `admin/compliance` 页已列出这四个待办） |
| 公安备案号 | 页面底部展示 |

**不给会怎样**：只能内部试点/局域网演示。境内公网提供服务属于违规，应用商店也无法上架。

> 说明：Supabase 项目在 us-east-1。**数据库可以先留在境外做开发验证**，但正式面向境内用户时，数据落地境外会牵涉数据出境合规，届时需要把库迁到境内（自建 Postgres 或境内托管），这部分是独立工程，不在本次交付范围。

## 6. 手机号登录（短信验证码）

**用途**：免邮箱注册，转化率更高。

**需要两样东西**

1. **短信服务**：阿里云短信 <https://dysms.console.aliyun.com> 或腾讯云短信 <https://console.cloud.tencent.com/smsv2>。要申请：签名（如「第三世界」）+ 模板（验证码模板）。签名需要**已备案域名或 App 备案号**，模板审核 1–2 小时。
2. **接进 Supabase**：Supabase 自带 phone auth 走 Twilio / MessageBird / Vonage（境外，境内到达率差且贵）。境内正确做法是 **Send SMS Hook**——在 <https://supabase.com/dashboard/project/bffuuxdnztowlwbxjlzp/auth/hooks> 配置一个 HTTP Hook 指向 Edge Function，由该函数调阿里云短信 API。这需要第 4 项（PAT）。

**不给会怎样**：只能邮箱+密码登录。当前就是这样。

## 7. 微信登录

**用途**：国内 App 最常见的登录方式。

**在哪拿**：微信开放平台 <https://open.weixin.qq.com> → 注册开发者（**企业主体，需 300 元/年认证费**）→ 创建「移动应用」→ 提交 App 信息与应用签名 → 审核通过后拿到 `AppID` 与 `AppSecret`。

**填到哪**：`AppSecret` 只能放服务端（Edge Function 环境变量），前端只放 `AppID`。回调地址填 Supabase 的 `/auth/v1/callback`。

**不给会怎样**：只能邮箱登录。个人主体拿不到移动应用资质，这一步必须是企业。

## 8. 设备数据接入（COROS / Garmin）

**现状**：本项目的 COROS 连接器已可用（授权后可读取**你自己账号**的训练与健康数据），适合内部验证；但**给用户用**需要厂商的合作资质。

| 厂商 | 入口 | 门槛 |
|---|---|---|
| Garmin | Garmin Connect Developer Program：<https://developer.garmin.com/> → Health API | 需企业资质 + 商务审核，签署协议后给 OAuth 凭据 |
| COROS | 无公开自助入口，需商务对接（COROS 开放平台） | 同上 |

**不给会怎样**：只能手动录入 / CSV 导入。当前产品设计里「手动录入」是完整可用的路径，不是降级方案。

## 9. 监控与告警（可选，但上线前建议有）

**用途**：前端报错、慢查询、RPC 失败率。现在只能靠用户口述「打不开」。

**在哪拿**：Sentry <https://sentry.io> → 新建 Project（Browser）→ 拿 DSN（形如 `https://xxx@o123.ingest.sentry.io/456`）。

**填到哪**：在 `prototype/index.html` 引入 SDK 并 `Sentry.init({ dsn })`。**建议先在 Edge Function / 反代上做错误日志，再接 Sentry**，避免把用户隐私字段带出去。

**不给会怎样**：线上出问题只能看 Supabase 日志，定位慢。
