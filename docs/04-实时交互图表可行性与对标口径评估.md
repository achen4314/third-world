# ARC 训练 · 实时交互图表可行性与对标口径评估（v1.1）

> 本文基于 `prototype/` 现有 **36 个界面 + 13 类浮层** 逐一评估，且评估结论已**同步实现进原型**（`prototype/live.js`）。组织顺序按你指定的五部分：① 界面清单与可行性 ② 图表能力 ③ 评分与阈值 ④ 数据融合与内部实现 ⑤ DEMO 与免责声明。

## 0. 本次确认口径与边界变更说明

| 项 | 确认结果 |
|---|---|
| **`AWCR`** | **一律按 ACWR（Acute:Chronic Workload Ratio）处理**，不再列为待确认项；Registry 中 `AWCR` 仅作为别名登记，不改公式。原型提供 `acwr.ewma`（主口径）与 `acwr.rolling`（并列展示）两种口径。 |
| **专有评分** | 按本次确认，**纳入原型级还原**：复现公开资料可查的评分名称、刻度、阈值分档、状态标签与状态含义；使用 **DEMO 占位值**；**不实现、不宣称还原** EPOC / Firstbeat / 自适应基线等真实算法。 |
| **传感器融合** | 按本次确认，**纳入原型级还原**：复现数据来源清单、字段映射、融合处理链与 App 内部实现要点；明确标注这是**自研原型实现要点（对标能力域）**，不是任何厂商 App 内部实现或标定参数的还原。 |
| **还原上限** | **以原型级还原为限，不编造真实厂商算法或医学结论**。厂商界面资产 / 图标 / 配色素材不复制；厂商云端 API 未取得授权前不接入。 |
| **数值与免责** | 所有数值统一标记 **DEMO**；明确**不构成训练或医学建议**。 |

> **与 v1.0 的关系**：`docs/01`–`03` 与 `README.md` 中的「不还原专有评分」边界，按本次确认调整为「**原型级对标占位还原**」。ARC 自身的决策层仍使用可解释规则（今日主状态、R-xx 规则），对标评分只作为**独立标注的对标展示区**，不参与训练建议生成。法律与合规边界（无源码逆向、无算法等价声明、无医学结论、需授权 API 不假设可用）**继续保留**。

**术语约定**：界面 = 一条路由（`P` 中的一个页面对象）；一级页 / 二级页 / 浮层与 `docs/01` 一致；卡片 = 页面内的 `card` 区块；图表 = `chart-host` 内的 SVG 或热力网格；口径 = `metric_id + calc_version`；窗口 = 7 / 28 / 42 / 90 日；来源 = `source ∈ device / api / import / manual`；版本 = LiveStore 的 `version`。

**可行性图例**：`● 高` 已具备数据管道与图表位，已实现；`◐ 中/受限` 仅特定状态（采集中 / 任务进行中 / 低频聚合）适用；`— 不适用` 不新增实时图表，并给出原因。

## 2.4 空 / 加载 / 异常反馈与状态一致性

**五种状态（实时控制条可现场切换验证）**

| 状态 | 触发条件 | 图表反馈 | 用户动作 |
|---|---|---|---|
| `ok` | 默认；刷新成功 | 正常渲染 + 实时指示器脉冲 | — |
| `loading` | 首次加载 >200 ms；手动刷新；筛选重算超过阈值 | **骨架条**保持卡片尺寸；>8 s 自动转 `error` | 可取消 |
| `empty` | 真无数据；筛选后无结果 | 「暂无数据 · 不显示 0」；筛选后无结果显示「筛选后无结果」并给**清除筛选** | 「去录入」→ `data/import`；「清除筛选」 |
| `error` | 4xx（不重试，给可读原因）；5xx 退避重试 3 次仍失败；超时 | 「数据加载失败 · 保留上一版快照」，**不静默吞错、不显示堆栈** | 「重试」→ `manual.refresh` |
| `offline` | `TypeError: Failed to fetch` / SSE 断连 | 图表降饱和 + 「离线 · 本地快照 HH:MM:SS · DEMO」角标；恢复后按 `version` 补齐增量 | 自动重连 |

**缺测与空的区别**：缺测是**有效数据集中某个点为 NULL**，图上显示虚线空位与「—」，并在 O1 给出原因（有效天数不足 / `sd=0` / 无功率数据 / 未标定）；`empty` 是**整个数据集无内容**。两者不可混用，缺测绝不按 0 补齐。

**状态一致性（硬性规则）**

1. 单一快照：`LiveStore` 保存不可变 `snapshot + version`；所有图表、指标卡、表格、浮层订阅同一版本，**不允许出现 A 卡新值 / B 卡旧值**。
2. 口径随数据走：每个派生值携带 `metric_id + calc_version`；刷新后所有卡显示同一 version；历史结果保留其计算时的版本，不追溯改写。
3. 筛选集中：窗口 / 来源 / 上下文 / 同条件筛选状态集中在 `LiveStore`，跨一级页切换保留，跨设备端（iPhone / iPad / Mac）语义一致。
4. 乐观更新与回滚：测试写入先就地追加，失败则回滚到上一 `version` 并给出 Toast。
5. 断线补齐：SSE 重连后按 `Last-Event-ID` / `version` 请求增量，不重放整段历史。
6. 权限变更：角色切换后所有实时卡片按 RBAC 即时重算可见范围，无权限显示**锁定态 + 原因**，不静默隐藏。
7. 跨端一致：三端共用同一套 `renderChart` 与 `LiveStore`；只改变列数与导航控件形态，不改变数据、口径与状态定义。

# 三、评分与阈值

## 3.1 `AWCR` 一律按 `ACWR` 处理

- `AWCR` 在 `metric-registry` 中仅作为 **ACWR 的别名**登记，**不改公式、不新增第二套口径**。
- 原型提供 `acwr.ewma`（λ = 2/(7+1)、2/(28+1)，**推荐主口径**）与 `acwr.rolling`（7 / 28 日均值比，并列展示以暴露数学耦合）两种口径；rolling 在 7 日有效天不足 7 时返回「不可计算」。
- `TL / TM / TS` 仍为 Training Load / Training Monotony / Training Strain；`sd = 0` 或有效天数不足时 TM / TS 返回「不可计算」，不输出 0 或 ∞。

## 3.2 还原范围与不还原范围（明确边界）

| 项 | 本原型 | 说明 |
|---|---|---|
| 评分名称、刻度、阈值分档、状态标签与状态含义 | ✅ **原型级还原** | 仅采用厂商**公开说明书 / 支持中心 / 官方技术页**可查的内容，逐项标注依据等级与来源 |
| 分档带的界面表达（分档条 + 当前值标记） | ✅ 原型级还原 | 使用 ARC 自有组件，不复制厂商界面资产 |
| DEMO 占位数值 | ✅ | 由占位生成器给出，与厂商设备真实输出**无对应关系** |
| 公开资料之间的差异 | ✅ 并列标注 | 不选一为「唯一正确」、不合并、不补造 |
| **真实算法** EPOC / Firstbeat Analytics / 自适应基线 / 厂商模型权重 | ❌ **不实现、不宣称还原、不编造** | 只复现「显示语义」，不复现「计算过程」 |

## 3.3 八个评分的完整口径与阈值分档

### S1 EvoLab 训练状态 · Intensity Trend（COROS）

- **公开口径（A）**：`Intensity Trend = Load Impact（7 日）/ Base Fitness（42 日）`；官方帮助中心给出 5 个疲劳区间，`Optimized 100–149%` 为最大化训练效率区间，`Performance 50–79%` 适合比赛日。

| 0–49% | Decreasing 下降 | 近期负荷低，基础体能下降 |

- **依据**：`support.coros.com / EvoLab`。

## 4.4 传感器融合与处理链（自研原型实现要点）

| 步骤 | 实现要点 |
|---|---|
| ① 采集 | BLE 通知 / 文件解析 / 表单提交 → `RawSample`，强制写 `source` 与 `quality_flag` |
| ② 时间对齐 | 统一 `ts_ms` (UTC)，估计设备时钟漂移；重采样到统一栅格但**缺测不插值** |
| ③ 坐标与去重力（IMU） | 静止段估计重力向量 → 坐标对齐 → 去重力 |
| ④ 滤波与积分（IMU） | 低通滤波（截止频率**待真机标定**）→ 积分得速度 → ZUPT 消漂移 |
| ⑤ 事件切分 | 速度阈值切分重复；视频按起跳 / 落地帧切分腾空与接触段 |
| ⑥ 纯函数计算 | `vbt-engine` / `jump-engine` / `hrv-engine` / `sleep-engine` / `load-engine`，输出带 `calc_version` |
| ⑦ 登记与审计 | `metric-registry` 登记公式 / 窗口 / 输入 / 证据编号；`audit-log` 留 `request_id` |
| ⑧ 事件分发 | SSE 推送 `device.sample` / `import.progress` / `sync.done`；worker 幂等 + 死信队列 |
| ⑨ 单一快照 | `LiveStore` 保存不可变 `snapshot + version`，所有图表订阅同一版本 |
| ⑩ 展示与下钻 | 图表适配层读同一快照；任意派生值可下钻到原始样本与计算口径 |

**IMU 统一导入 schema（DEMO）**：`{ device_id, sample_rate_hz, unit:{acc:"m/s^2",gyr:"rad/s"}, source:"import", session_id, exercise, load_kg, samples:[{ts_ms, ax, ay, az, gx, gy, gz}] }`。手动填入最小字段：`exercise, load_kg, rep_index, mpv_or_mcv, velocity_loss_pct, method=manual`。

## 4.5 治理规则（融合的硬约束）

| 规则 | 约束 |
|---|---|
| 来源互斥 | 同一指标 `device / api / import / manual` 在筛选时互斥，**不合并计算**；筛选时非匹配点置 `null` 并显示「—」 |
| 缺测不补 | 缺测写 `NULL` 并显示「—」；窗口指标有效天数不足返回「不可计算」，**不补 0、不插值、不估算** |
| 质量标记 | `quality_flag ∈ valid / suspect / missing`；`suspect` 进质量页，不静默丢弃 |
| 冲突检测 | 同一 `ts_ms` 多来源同指标时记录冲突，**不自动覆盖**，交人工或规则裁决 |
| 版本一致 | 每个派生值携带 `calc_version`；刷新时所有卡片切到同一 `version` |

## 4.6 App 内部实现要点（分层与模块边界）

| 层 | 模块 | 职责约束 |
|---|---|---|
| 接入层 | `ble-gateway` / `file-importer` / `api-connector` / `manual-entry` | 只产出 `RawSample`，不写业务逻辑 |
| 存储层 | `timeseries-store` / `session-store` / `metric_definition` | 原始样本只追加不覆盖；数据库变更走可回滚迁移 |
| 计算层 | 纯函数 + 显式 `calc_version` | 不依赖 UI、不依赖具体设备、可回归测试 |
| 服务层 | `metric-registry` / `rule-engine` / `audit-log` | 四问准入：公式、窗口、输入、证据编号 |
| 实时层 | SSE event bus / `LiveStore` / refresh controller | 单向推送、心跳、断线退避重连、按 `version` 补增量 |
| 展示层 | chart adapter / tooltip / filter / state overlay | 筛选与悬停不回源；刷新全卡同步更新 |
| 任务层 | worker（独立进程）/ DLQ | 幂等键 = `import_id + calc_version`，失败最多 3 次后进死信并告警 |

**原型内部实现锚点**：`prototype/live.js`（`ARC_LIVE.state` 单一快照 + 交互引擎）→ `prototype/app.js`（`renderChart` / `mountCharts` / `ARC.adapter` 替换点）→ `prototype/data.js`（`METRICS` Registry）→ 生产 `server/features/ingest`、`core-metrics`（纯函数）、`realtime/sse`、`worker`。

## 4.7 未取得授权 / 未标定的边界

- 厂商云端 API（COROS 开放平台、Garmin Connect Developer Program）状态为「**未申请**」；ANT+ 为「**需授权**」；HealthKit / Health Connect 为「**未授予**」。原型不假设可用。
- IMU 低通截止频率、ZUPT 阈值、V1RM、LVP 最小 R²、PPO / FVP 系数等**留空 = 未标定**；原型中 1RM、PPO / FVP 等依赖项显示「— / 不可计算」，写入标定值后才计算（`lab/calibration` 可现场演示）。
- FTMS 各厂商实现存在差异，字节布局须以实现时官方 GATT 规范文本与真机验证为准；不一致样本标记 `quality_flag=suspect`。
