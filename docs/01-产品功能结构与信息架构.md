# ARC 训练 · 产品功能结构与信息架构规格（v1.0）

> 交付定位：面向 iPhone / iPad / Mac 的**综合运动训练操作系统原型**的开发前规格。本文定义「有什么、放在哪、怎么跳、谁能看、边界在哪」，视觉与动效数值见 `02`，技术实现见 `03`，可点按的原型见 `../prototype/index.html`。
> 配套基线：`/Users/mac/Desktop/运动训练软件_独立重建方案.md`（下称《重建方案》）。本文沿用其数据治理约束与指标口径。

## 0. 口径与边界声明（先于功能，不可略过）

| 项 | 本规格的确定口径 | 说明 |
|---|---|---|
| `AWCR` | **一律按 ACWR（Acute:Chronic Workload Ratio）实现**，同时提供 rolling 与 EWMA 两种口径 | **本次已确认，不再列为待确认项**。`metric-registry` 中 `AWCR` 仅作 `acwr.*` 的别名登记，不改公式。若后续给出不同定义，新增独立 `metric_id` 而不改写既有口径 |
| `TL / TM / TS` | Training Load / Training Monotony / Training Strain | 取自 Foster 等（2001）7 日窗口定义；`sd=0` 时 TM 与 TS 返回「不可计算」，不输出 0 或 ∞ |
| 竞品「全部功能范围」 | **按功能域做能力覆盖；专有评分的*显示语义*按 `docs/04` 做原型级对标占位还原，专有算法仍不实现** | COROS EvoLab / Intensity Trend / Recovery Timer、Garmin Training Effect / Body Battery / HRV Status / 睡眠分数等：**公开可查的名称、刻度、阈值分档与状态含义**做 DEMO 占位还原；**EPOC / Firstbeat / 自适应基线等真实算法不实现、不宣称等价**；ARC 决策层仍用可解释的 CTL/ATL/TSB、ACWR、TM/TS、RMSSD/lnRMSSD、TST/WASO/效率 |
| My Jump Lab「全部功能范围」 | **按公开方法逐项实现能力清单** | 跳跃、VBT、冲刺/变向、活动度、Wellness、腘绳肌、力-时间曲线、视频/IMU/手填三通道、多用户、历史、CSV 导出；不还原其内部实现 |
| Enode Pro 类 VBT IMU | 实现**采样数据拉取 / 导入 / 手填 + 公开 VBT 指标计算** | 不还原其传感器融合、滤波与标定实现；采样率、滤波截止、ZUPT 阈值均为需真机标定的配置项 |
| 数据治理 | 每条样本带 `source` 与 `quality_flag`；**缺测显示「—」，不插值、不补零、不估算、不合并**；同指标多来源在筛选时互斥 | 《重建方案》S2、§三.7 |
| 原型数据 | 原型内所有数值为**演示样例（DEMO）**，界面常驻「演示数据」标记 | 不得当作真实运动数据或医学结论 |

## 1. 产品定位与三条主线

**一句话**：把「设备 → 原始样本 → 派生指标 → 负荷/周期 → 决策」做成一条可下钻、可解释、可审计的链路。

- **主线（唯一）**：`负荷 → 恢复 → 表现`。所有分析页面都挂在这条线上，不允许出现第四条并列主线。
- **反堆叠铁律**：每个页面只回答**一个问题**。图表、表单、设备状态、团队信息不同屏堆叠。
- **优于 COROS 手机端的四个具体抓手**（可验收）：
  1. **单一主状态**：今日页只给一个由规则引擎生成且**附三条依据**的结论，而不是 12 个并排小组件。
  2. **口径可见**：每个指标旁常驻「口径 / 窗口 / 来源」三枚芯片，点按即下钻到公式版本、输入、证据编号与原始样本。
  3. **渐进披露**：默认路径一步可见；高级口径、阈值、标定参数收进第二层 Sheet，不在主屏暴露。
  4. **跨端同构**：iPhone / iPad / Mac 使用**同一套导航语义、同一套组件、同一套数据**，只改变列数与导航控件形态（Tab Bar ↔ Sidebar），不重新设计页面。

## 3. 信息架构总览

```
ARC 训练
├── 工作区 A：运动员工作区（默认）           ← 5 个一级页，iPhone 用 Tab Bar
│   ├── P1 今日 Today
│   ├── P2 训练 Train          ─┐
│   ├── P3 分析 Analyze        ─┼─ 每个一级页下挂 4–6 个二级页（只到第二层）
│   ├── P4 测试 Lab            ─┤
│   └── P5 数据 Data           ─┘
├── 工作区 B：教练工作台 / 后台管理          ← 独立边界，7 个二级页
│   └── P6 管理 Admin
├── 浮层层 O：Sheet / Popover / Alert / HUD  ← 随处可调起，不占导航层级
└── ⌘K 命令面板（Mac / iPad）                ← 跨层级直达，不新增页面
```

**层级硬约束**：导航最多两层。第三层信息一律用 Sheet / 下钻面板表达，不新增页面、不增加返回栈深度。这是「比 Training Hub 更逻辑明确」的结构性保障。

## 7. 模块边界（防止功能堆叠的核心约定）

| 边界 | A 侧 | B 侧 | 判定规则 |
|---|---|---|---|
| **分析 ↔ 数据看板** | `analyze/*` = 单运动员、长周期、**可下钻到原始样本**、可切换口径 | `admin/overview` = 多运动员聚合、**只读**、最多下钻到成员页，**不显示样本级数据** | 看板出任何趋势图，都必须能回答「聚合口径与样本量」；不允许在看板里改口径 |
| **测试 ↔ 分析** | `lab/*` = **采集与写入**、实时反馈、设备/录入通道 | `analyze/*` = **只读再计算与对比** | 测试页不显示 90 日趋势；分析页不提供录入控件 |
| **今日 ↔ 其余全部** | `today` = 一个结论 + 三个入口，无图表堆叠 | 其余页承载全部细节 | 今日页新增任何卡片前，先回答「它是否属于这一个结论」 |
| **数据（个人）↔ 管理（组织）** | `data/*` = 本人设备、本人授权、本人缺测 | `admin/fleet` = 设备资产、批量任务、凭据与保留策略 | 个人页不显示组织级配置；管理页不直接编辑个人样本 |
| **指标口径 Registry ↔ 分析** | `data/metrics` = 公式与版本的**唯一定义源** | 分析页只**引用**，不重新定义、不内置第二套公式 | 任何指标卡的下钻 Sheet 从 Registry 取数；分析页禁止硬编码公式文本 |
| **弹层 ↔ 页面** | Sheet/Popover/Alert = 聚焦任务、第三层信息、即时确认 | 页面 = 可收藏、可返回、可分享的持久位置 | 需要 URL / 返回栈 / 分享的内容一律做成页面，不做成 Sheet |

## 10. 页面板块规范（统一骨架）

所有二级页使用同一骨架，跨端只改列数：

```
[面包屑]  [页面标题 + 一句话问题]  [口径 / 窗口 / 来源 三枚芯片]  [主操作按钮]
────────────────────────────────────────────
[主视图区]   1 个主图表 或 1 个主表单（页面焦点，唯一）
────────────────────────────────────────────
[支撑区]     2–4 张支撑卡 / 数据表 / 规则说明（不与主视图争焦点）
────────────────────────────────────────────
[下钻区]     「查看原始样本」「口径说明」「相关页面」统一置于页尾
```

- **今日页例外**：主视图 = 主状态卡（结论 + 三条依据），支撑区 = 3 张卡，无图表。
- **管理页例外**：主视图 = 聚合图表 / 表格，左侧固定子导航。
- 每页最多 **1 个主操作按钮**（渐变实心），其余为次要按钮；避免 COROS 手机端常见的多入口竞争。

## 12. 原型演示数据声明

原型中出现的全部数值（负荷、HRV、睡眠、VBT、跳跃、设备、团队、**对标评分占位值、融合映射示例字段**）均为**标记为 DEMO 的样例数据**，用于验证布局、计算链路与交互；其中 CTL/ATL/TSB、ACWR 双口径、TM/TS、跳跃高度、RSI、速度损失均由原型内的公式**实际计算**得出，而非硬编码结果。缺测日以 `null` 参与计算并显示「—」。这些数值**不是真实运动员数据，也不是任何厂商设备的真实输出，不构成训练或医学建议**。

**v1.1 补充**：按本次确认口径，`AWCR` 一律按 `ACWR` 处理；专有评分的公开显示语义与数据融合的来源 / 字段映射 / 内部实现要点已在 `docs/04` 与原型（`live.js`、O12 / O13 浮层）中做**原型级对标占位还原**，还原上限与免责声明见 `docs/04` §0、§5。
