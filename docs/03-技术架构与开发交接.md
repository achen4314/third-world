# ARC 训练 · 技术架构与开发交接（v1.0）

> 面向「可直接进入开发」的落地文档。原型 `../prototype/` 是**零构建、可点按的规格可执行版**，其数据适配器可直接替换为本文定义的 API 客户端。

---

## 0. 决策记录（先决策，后写代码）

### 0.1 需求六问（用户未指定，按原型目标做默认假设，可一行改）

| 问 | 决策 | 理由 |
|---|---|---|
| 技术栈 | **交付目标**：SwiftUI 多平台单 Target（iOS/iPadOS/macOS）+ TypeScript/Node 后端；**原型**：零构建 HTML/CSS/JS | 单 Target 用 `NavigationSplitView` 天然满足「同语义导航、仅列数不同」；零构建原型让设计与产品评审无需装环境即可在 iPhone/Mac/iPad 浏览器打开 |
| 服务形态 | **全栈单体 + 独立 worker 进程** | 领域内聚、部署简单；计算密集的 IMU/导入/聚合必须移出请求进程 |
| 数据库 | **PostgreSQL + TimescaleDB**（时序）+ Redis（缓存/队列） | 原始样本为只追加时序，派生值为关系型；两者都需可回滚迁移 |
| 接口方式 | **REST + OpenAPI 3.1 → 生成类型化客户端** | 多端（Swift / Web 管理台）共享类型，避免手写 DTO 漂移 |
| 实时能力 | **SSE**（设备实时流、导入进度、同步状态）+ 离线回传队列 | 单向服务端→客户端即可，SSE 自带重连、穿透代理更简单；WebSocket 的双向能力在此无用 |
| 认证 | **JWT 短时效访问令牌（15min）+ 服务端存储刷新令牌（httpOnly Cookie）+ RBAC** | 令牌不进 localStorage、不进 URL；7 类角色由服务端强制 |

### 0.2 架构决策（各一句理由）

| 决策 | 选择 | 理由 |
|---|---|---|
| 项目结构 | **feature-first**（`src/features/<domain>/{controller,service,repository,dto}`） | 计算层、设备层、管理后台各自可独立交付与测试 |
| API 客户端 | **OpenAPI codegen + 类型化 fetch 封装**（Web）；Swift 用生成模型 + `URLSession` | 跨端类型单一来源，避免三套手写模型 |
| 认证策略 | JWT access + refresh rotation + RBAC 中间件 | 无权限时返回结构化 403，前端显示锁定态而非隐藏入口 |
| 实时方案 | SSE + 事件总线；后台任务独立进程 | 长任务不进请求处理器；任务幂等、失败重试、死信 |
| 错误处理 | 类型化错误类 + 全局处理器 + `request_id` | 客户端只见规范化结构，绝不返回堆栈 |
| 计算层 | **纯函数 + 显式口径版本号**，不依赖 UI / 设备 / HTTP | 每个指标可回归测试、可下钻、可回滚 |

## 1. 两条产出轨道

```
轨道 A（本次交付）：prototype/  ← 可点按、三端视图、真实公式计算、DEMO 数据适配器
                                    └─ 替换 adapter → 对接轨道 B 的 API，即进入开发
轨道 B（目标工程）：apps/        ← SwiftUI 多平台 App（iPhone/iPad/Mac）
                    server/      ← Node + Fastify + PostgreSQL/TimescaleDB + Redis
                    worker/      ← IMU 处理、文件导入、日聚合、报告生成
                    admin-web/   ← 管理后台（可复用 prototype 的组件规范）
```

**跨端契约**：三端共用同一份 OpenAPI schema 与同一套语义色/字号 token；SwiftUI 侧用 `@Environment(\.horizontalSizeClass)` 切换 compact/regular，不按设备名分支。

## 2. 工程目录（feature-first）

```
server/
  src/
    config/index.ts              # 集中配置 + 启动时 zod 校验，缺失即 fail-fast
    shared/
      errors/{AppError,NotFound,Validation,Forbidden}.ts
      middleware/{requestId,logger,errorHandler,auth,authorize,validate,rateLimit}.ts
      database/{pool,migrations,transaction}.ts
      logging/logger.ts          # 结构化 JSON + request_id
      realtime/sse.ts
      cache/redis.ts             # 一律带 TTL + 写后失效
    features/
      devices/{controller,service,repository,dto,ble-gateway,file-importer}.ts
      ingest/{controller,service,repository,dto,manual-entry,fit-parser,imu-import}.ts
      load/{controller,service,repository,dto,tl,ctl-atl,acwr,monotony}.ts
      recovery/{controller,service,repository,dto,hrv,sleep}.ts
      vbt/{controller,service,repository,dto,imu-pipeline,lvp}.ts
      jump/{controller,service,repository,dto,flight-time,fvp}.ts
      performance/{controller,service,repository,dto,power,zones}.ts
      plan/{controller,service,repository,dto,rule-engine}.ts
      metrics/{registry,versions}.ts     # 唯一定义源：公式/窗口/输入/证据/版本
      reports/{controller,service,export}.ts
      admin/{athletes,roles,fleet,rules,audit,compliance}.ts
    app.ts  # /health /ready、CORS 显式来源、安全头、优雅停机
  migrations/  # 全部可回滚
  openapi.yaml
  .env.example
worker/
  jobs/{imu-process,import-file,daily-aggregate,report-render}.ts
  dlq.ts  # 幂等 + 最多 3 次重试 + 死信告警
```

**三层铁律**：Controller 只解析/校验/格式化；Service 承载业务规则与事务编排，**不 import HTTP 类型**；Repository 只查库与外部调用。计算层（`tl`、`acwr`、`imu-pipeline` 等）是纯函数，独立包 `core-metrics/`，可被 Swift 端复用同一套公式定义（JSON 口径表）。

## 4. Metric Registry：每个指标必须回答四问

> 回答不了「公式 / 窗口 / 输入 / 证据编号」的指标不允许上线。原型 `data.js` 的 `METRICS` 与下表同源。

| metric_id | 公式 / 口径 | 窗口 | 输入 | 证据 | 版本 |
|---|---|---|---|---|---|
| `tl.trimp` | `D·HRr·0.64·e^(1.92·HRr)`（男）/ `0.86·e^(1.67·HRr)`（女），系数按选定文献固定 | 单次 | HR 时序、HRrest、HRmax | E5 | v1.2 |
| `tl.srpe` | `sRPE × 时长(min)` | 单次 | RPE、时长 | E6 | v1.0 |
| `tl.tss` | `IF=NP/FTP`；`TSS = t·NP·IF/(FTP·3600)·100`；**无功率不可用** | 单次 | 功率、FTP | E7 | v1.0 |
| `ctl` / `atl` | `CTL_t = CTL_{t-1} + (TL_t−CTL_{t-1})/42`；ATL 同式 /7 | 42 / 7 日 EWMA | 日 TL | E7 | v1.0 |
| `tsb` | `TSB_t = CTL_{t-1} − ATL_{t-1}`（前一日差值口径，固定并展示） | 日 | CTL、ATL | E7 | v1.0 |
| `acwr.rolling` | `mean(TL,7d)/mean(TL,28d)`；有效天数不足 → 不可计算 | 7 / 28 日 | 日 TL | E8 | v1.0 |
| `acwr.ewma` | `acute += .25(TL−acute)`；`chronic += .069(TL−chronic)`；比值 | λ=2/(7+1)、2/(28+1) | 日 TL | E8 | v1.0（**推荐主口径**） |
| `tm` | `mean(TL,7d)/sd(TL,7d)`；`sd=0` → 不可计算 | 7 日 | 日 TL | E6 | v1.0 |
| `ts` | `sum(TL,7d) × TM`；TM 不可计算则 TS 不可计算 | 7 日 | 日 TL、TM | E6 | v1.0 |
| `hrv.rmssd` / `lnrmssd` | `sqrt(mean(ΔRR²))` / `ln(RMSSD)`；7/28 日基线 ±SD | 日 / 7 / 28 | RR 间期 | E9 | v1.0 |
| `sleep.*` | actigraphy 分期或授权数据源 → TST/WASO/效率/觉醒/规律性 | 夜 | 腕动 / HealthKit | E10 | v1.0 |
| `vbt.mcv/mpv/pv` | 去重力→低通→积分→ZUPT→重复切分后的速度统计 | 每次重复 | IMU / 手填 | E11 | v0.9（待真机标定） |
| `vbt.vl` | `(v_best−v_last)/v_best × 100`；10/20/30% 为可配置阈值，非事实 | 每组 | 重复速度序列 | E11 | v1.0 |
| `vbt.lvp` / `vbt.1rm` | `V = a·kg + b`（记录 R²）；`1RM=(V1RM−b)/a` | 一次测试 | 多组负荷-速度对 | E11 | v0.9 |
| `vbt.power` | `P=F·v`，`F=m(a+g)`；等速近似 `P≈mgv` 须标注口径 | 每次重复 | 速度、加速度、负荷 | E12 | v0.9 |
| `jump.height` | `h = g·t_f²/8`，`g=9.81`；视频法 `t_f=(f_land−f_take)/fps` | 每次跳跃 | 腾空时间 / 帧号 + fps | E13 | v1.0 |
| `jump.rsi` | `h/t_contact`（DJ）；连续跳用 `t_f/t_contact` 变体，口径固定 | 每次 | 高度、接触时间 | E13 | v1.0 |
| `jump.ppo` / `jump.fvp` | Sayers 等经验式 / Samozino 等剖面；**系数从配置读取，不硬编码猜测值** | 每次 | 体重、高度、推蹬距离 | E12 E13 | v0.8（配置未标定） |

**本次确认：`AWCR` 一律按 `ACWR` 处理**，不再列为待确认项。Registry 中登记为 `acwr.*` 的**别名**，不改公式；若后续给出不同定义，新增独立 `metric_id` 而非改写现有口径。

## 6. 实时、后台任务与缓存

- **SSE**：`/api/v1/events` 按 `athlete_id` / `org_id` 订阅，30s 心跳，断线 3s 退避重连；事件只携带增量与 `request_id`。
- **后台任务**（独立进程）：IMU 处理链、文件导入解析、日负荷聚合、周期报告渲染。全部**幂等**（以 `import_id + calc_version` 为幂等键），失败重试最多 3 次后进死信队列并告警。
- **缓存**：`analysis/*` 结果 TTL 5min；`profile` 15min；`metrics` 定义 60s；写样本 / 改口径 / 改个体参数后**立即失效**对应键。禁止无 TTL 缓存。
- **离线**：移动端本地队列缓存原始样本，恢复连接后按 `device_id + ts_ms` 去重回传，回传进度由 SSE 反馈。

## 7. 配置、错误、日志与安全

`.env.example`（只提交占位值，真实 `.env` 进 `.gitignore`）：

```dotenv
NODE_ENV=development
PORT=3001
DATABASE_URL=postgresql://user:password@localhost:5432/arc
REDIS_URL=redis://localhost:6379
JWT_SECRET=replace_me_with_a_real_secret
JWT_EXPIRES_IN=15m
REFRESH_TOKEN_TTL_DAYS=30
CORS_ORIGINS=https://app.example.com,https://admin.example.com
S3_BUCKET=arc-imports
S3_REGION=ap-guangzhou
IMU_LOWPASS_HZ=            # 真机标定后填写，留空 = 未标定
IMU_ZUPT_THRESHOLD=
V1RM_BACK_SQUAT=
LVP_MIN_R2=
RULE_ENGINE_VERSION=v1.0
LOG_LEVEL=info
```

- **启动校验**：`config/index.ts` 用 zod 校验必填项，缺失立即退出（fail-fast）；可标定参数允许为空但**不得填猜测默认值**，未标定时相关指标返回「不可计算」。
- **中间件顺序**：`RequestID → Logging → CORS → RateLimit → BodyParse → Auth → Authz → Validation → Handler → ErrorHandler`。
- **日志**：结构化 JSON，含 `request_id`、`actor_id`、`duration_ms`；**不记录密码、令牌、RR 间期原始值等隐私数据**。
- **安全**：CORS 显式来源（生产禁 `*`）、helmet 安全头、公开端点限流、HTTPS、预签名 URL 上传（>5MB 文件不穿 API 服务）、优雅停机（SIGTERM 排空连接后关闭连接池）。
- **前端错误映射**：4xx 不重试、5xx 最多 3 次退避、`TypeError: Failed to fetch` 显示离线横幅；所有错误映射为可读文案，不暴露内部细节。
