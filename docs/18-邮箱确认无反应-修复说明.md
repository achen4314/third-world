# 邮箱确认「点了没反应」——定位与修复

> 2026-11-15 22:20 · 线上 `trthirdworld.online` 已同步该修复

## 1. 现象与证据

用户反馈：收到确认邮件，点击链接后「没有任何反应」。

**服务端其实是成功的**。真实库 `auth.users` 实测（UTC → 北京时间 +8）：

| 邮箱 | 注册 | 确认（`email_confirmed_at`） | `last_sign_in_at` | 组织关系 |
|---|---|---|---|---|
| 今天新账号 | 18:38:02 | **18:38:19**（17 秒后） | 18:38:19 | **0 条** |
| 昨天账号 | 22:02:39 | 22:02:53 | 22:03:14 | 1 条 |
| `demo@third.world` | 种子 | 已确认 | — | 1 条 |

GoTrue 的 `/auth/v1/settings` 显示 `mailer_autoconfirm: false`、`external.email: true`、
`disable_signup: false` —— 确认邮件流程本身是开启且正常的。

所以问题不在发信、不在验证、不在数据库，**在「验证完之后回到应用」这一段**。

## 2. 根因：两层

**第一层（代码，主因）：应用完全不解析认证回调。**

GoTrue 验证 token 后会 302 回 `redirect_to`，并把会话放在 URL 上：

```
implicit : #access_token=…&refresh_token=…&expires_in=…&type=signup
PKCE     : ?code=…
出错     : #error=…&error_description=…&error_code=otp_expired
```

修复前 `initFromURL()` 只认 `platform/theme/role/route/window/source/status/live`，
`init()` 也只读 localStorage 里的旧会话。**链接带回的 `access_token` 被直接忽略**：
既不接管会话、也不给任何提示，页面看起来和没点过一样。
这解释了为什么「确认成功」和「没有反应」能同时成立。

**第二层（配置，可能因人而异）：回跳地址。**

`signUp` 修复前不传 `email_redirect_to`，GoTrue 用项目里的 **Site URL**。
若 Site URL 仍是 Supabase 默认的 `http://localhost:3000`，确认链接会把浏览器带到本机地址，
页面根本打不开——这是「没反应」的另一种表现。这一层只能在项目后台确认/修改。

另外：新账号 `memberships = 0`，登录后本来就会进入「先选一下你的身份」开通向导，
这是正常的下一步，不是卡死。

## 3. 已落地的修复

| 文件 | 改动 |
|---|---|
| `prototype/supabase-client.js` | 新增 `readAuthCallback()`：解析 implicit / PKCE / 错误三类回调；成功时 `setSession()` 接管会话并交给 `boot()`；把结果写入 `S.authCallback`；用 `history.replaceState` 清掉地址栏里的 token（保留 `sharecode` 等无害参数） |
| 同上 | `authRedirect()` 返回**当前这一页**的 URL（不是站点根）——分发页会二次跳转，hash 在跳转中会丢，所以必须直接回落到 `/iphone/`、`/ipad/`、`/mac/` |
| 同上 | `signUp()` 传 `email_redirect_to`；若项目白名单未登记而拒绝，自动降级重试一次（注册本身不被卡住），并把 `redirectRejected` 返回给界面 |
| 同上 | 新增 `resendConfirmation()`；`resetPassword()` 同样补 `redirect_to` 与降级，避免「忘记密码」链接也指向 localhost |
| 同上 | `emit()` 把 `authCallback` 推给 `ARC_DB_STATUS` |
| `prototype/ui-flows.js` | 登录页新增「没收到确认邮件？重发」；`DB.init()` 之后把回调结果明确显示出来（成功 toast + 绿色提示，失败红色提示）；注册成功文案改为「点链接会自动回到这里并登录」 |
| `prototype/app.js` | `ARC_DB_STATUS` 桥接保存 `dbAuthCallback` |

**立即生效的兜底**：账号已经确认成功的人，不需要再点任何链接，
**直接用邮箱 + 密码登录即可**。

## 5. 仍需在项目后台确认的一处（外部条件）

Supabase Dashboard → 项目 → **Authentication → URL Configuration**：

- **Site URL** 设为 `https://trthirdworld.online`
- **Redirect URLs** 添加：
  ```
  https://trthirdworld.online/**
  http://trthirdworld.online/**
  https://achen4314.github.io/**
  http://localhost:8799/**
  ```

不改也能用（应用现在会带 `email_redirect_to`，且被拒时自动降级），
但旧邮件里的链接仍会指向旧 Site URL。彻底干净的做法是改完后在登录页点一次
「没收到确认邮件？重发」，用新邮件走一遍。

诊断捷径：把邮件里那个链接**作为文本复制**出来（不要点击，token 只能用一次），
看 URL 里的 `redirect_to=` 是什么，就能 100% 确定 Site URL 当前值。
