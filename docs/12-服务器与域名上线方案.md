## 3. 域名解析核查证据

截图（阿里云云解析 DNS · `trthirdworld.online` 免费版）显示「NS 地址不一致」黄条，分配值为 `dns11.hichina.com` / `dns12.hichina.com`，记录列表「没有数据」。

本机实测：

```
dig +short NS trthirdworld.online  → dns11.hichina.com. / dns12.hichina.com.
dig +short A  trthirdworld.online  → （空）
dig +short A  www.trthirdworld.online → （空）
```

**判定**：
- 注册商处的 NS **已经**指向阿里云分配的两台（与控制台一致），黄条多半是控制台查询缓存 / 生效延迟，可点「重新查询」复核；这不是当前的主要阻塞。
- 真正的阻塞是 **A 记录 0 条**：域名现在解析不到任何 IP，浏览器打不开。
- 建议添加（部署后按实际域名）：

| 主机记录 | 类型 | 记录值 | 用途 |
|---|---|---|---|
| `app` | A | `47.95.117.212` | 前端 + 后台控制台入口（推荐，隔离 Dify） |
| `@` | A | `47.95.117.212` | 可选，主域也指向本应用 |
| `www` | CNAME | `app.trthirdworld.online` | 可选 |

**不要**把现有 Dify 正在用的域名记录改掉。

## 4. 比技术更靠前的合规阻塞

服务器在**华北 2（北京）**，属于中国大陆境内节点。要在中国大陆通过域名对外提供 Web 服务：

1. **ICP 备案**：域名 `trthirdworld.online` 需在腾讯云备案系统提交，主体 + 网站信息，管局审核通常约 20 个工作日。未备案时，云厂商会对 80/443 的域名访问做拦截。
2. **公安联网备案**：上线后 30 日内在 `beian.gov.cn` 办理。

## 5. 已开发完成的后台管理控制台（`deploy/`）

| 文件 | 作用 |
|---|---|
| `deploy/admin-console.mjs` | 零依赖 Node HTTP 服务，默认 `127.0.0.1:8787` |
| `deploy/admin/index.html` | 管理界面：口令登录、连接配置、状态巡检、维护动作、日志 |
| `deploy/nginx.arc-training.conf` | 独立 `server_name` 的 nginx 增量配置，按 Host 分流，**不改 Dify 的 server 块** |
| `deploy/arc-admin.service` | systemd 单元，最小权限（`www-data` / `NoNewPrivileges` / `ProtectSystem`） |
| `deploy/install.sh` | 幂等安装脚本，含本机自检与 DNS 检查 |

**能力**
- 配置管理：写 `SUPABASE_URL` / publishable key / 域名 / 是否允许运行时覆盖 → 直接生成 `prototype/env.js`（这正是「把数据库连接配到服务器上的应用」）。
- 状态巡检：主机负载与内存、磁盘、nginx 配置校验、服务状态、域名 A 记录、Supabase Auth 连通性。
- 日常维护：健康检查、nginx 校验、重载 nginx、重启管理服务、查看日志。

**安全边界**
- 只绑回环地址，公网入口由 nginx 反代；不额外开端口。
- 不设 `ARC_ADMIN_TOKEN` 直接拒绝启动；所有 `/api/*` 要 Bearer token。
- 维护动作是**固定命令白名单**，不接受客户端传来的命令字符串（已测：`{"name":"rm -rf /"}` 被拒）。
- 只接受 `sb_publishable_` 开头的 key（已测：`sb_secret_` 被拒）；GET 配置时 key 掩码回显；配置文件 0600。
- 不碰 Dify 配置、不碰数据库密码、不覆盖业务数据。

**本地冒烟测试**（`ARC_ADMIN_ROOT` 指向临时目录，未改动仓库里的 `env.js`）：
`401 未授权 → 带 token 读配置 → 状态巡检 7 项 → 保存配置并生成 env.js → 拒绝 secret key → 拒绝白名单外动作`，全部符合预期。

## 6. 拿到权限后的执行顺序（每步都有可验证结果）

```bash
# 0) 你提供 SSH 访问后，我先在服务器上做只读确认
ssh <user>@47.95.117.212 'systemctl list-units --type=service --state=running | head -30; docker ps --format "{{.Names}}"; ls /etc/nginx/conf.d/'
#     → 确认 Dify 的部署方式与现有 nginx 配置，避免撞车

# 1) 上传项目
rsync -av --exclude node_modules --exclude .env.local ./ <user>@47.95.117.212:/opt/arc-training/

# 2) 加 DNS 记录（你在云解析 DNS 控制台点，或给我有 DNS 权限的 AK）
#    app A 47.95.117.212 → 验证：dig +short app.trthirdworld.online

# 3) 一键安装（会把口令写进 /etc/arc-training/admin.env，0600）
ARC_ADMIN_TOKEN='<16 位以上随机串>' sudo -E bash /opt/arc-training/deploy/install.sh
#     → nginx -t 通过、服务 active、静态站 200、控制台 200、无口令 /api/ 401

# 4) 在后台 /admin/ 填 Supabase URL 与 publishable key → 保存
#     → 生成 /opt/arc-training/prototype/env.js；状态页 Supabase Auth 显示 200

# 5) 备案通过后签证书
certbot --nginx -d app.trthirdworld.online
#     → https 200；再加 HSTS
```

**验证清单**：`dig` 有 A 记录 / `curl -I http://app.trthirdworld.online/` 200 / `curl -I http://47.95.117.212/` 仍是 Dify 的 307（证明没打挂现有服务）/ `/admin/` 要口令 / 前端登录 demo 账号能读到真实库。
