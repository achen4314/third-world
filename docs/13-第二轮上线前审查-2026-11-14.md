## 1. 部署与可达性（本轮新增，全是 P0）

### P0-1 域名零 A 记录

- **证据**：`dig A trthirdworld.online @8.8.8.8` 与 `@223.5.5.5` 均**无返回**；云解析控制台
  「主机记录」列表显示「没有数据，共 0 条」。
- **已委托但未配置**：`dig NS` 返回 `dns11.hichina.com / dns12.hichina.com`，说明 NS 已经
  指向阿里云云解析，**只是里面一条记录都没加**。控制台那句「查询到的 NS 与云解析分配的
  NS 不一致」是缓存延迟提示，不是故障。
- **影响**：`https://trthirdworld.online` 在任何浏览器里都是 DNS 解析失败，上线=0 访问。
- **修法**：云解析 → `trthirdworld.online` → 添加记录，两条：

  | 主机记录 | 类型 | 记录值 | TTL |
  |---|---|---|---|
  | `@` | A | `47.95.117.212` | 600 |
  | `www` | A | `47.95.117.212` | 600 |

  验证：`dig +short A trthirdworld.online @223.5.5.5` 应返回 `47.95.117.212`（1–10 分钟生效）。

### P0-2 SSH 未授权，我进不去这台机器

- **证据**：`nc -z 47.95.117.212 22` → OPEN；但
  `ssh -i ~/.ssh/id_ed25519_thirdworld root@47.95.117.212` → `Permission denied (publickey,password)`。
  阿里云控制台「密钥」一栏显示「**暂未绑定**」。
- **影响**：部署动作一步都执行不了；现在所有部署产物只能停在本地。
- **修法**（二选一）：
  1. **绑密钥（推荐）**：控制台 → 左侧「密钥」→ 导入密钥 → 粘贴
     `~/.ssh/id_ed25519_thirdworld.pub` 的内容 → 绑定到实例 `Ubuntu-gaxl`。
  2. **给密码**：实例「远程连接」→ 重置 root 密码 → 把密码给我，我用 `expect` 登录后立刻
     改成密钥登录并关掉密码登录。

### P0-3 云防火墙没放行 443

- **证据**：`nc -z 47.95.117.212 443` → **closed**；而 22 / 80 是 OPEN。
  说明不是机器没起服务，是云侧安全组/防火墙只开了 22、80。
- **影响**：即使证书签下来，外网也连不上 443，HTTPS 全站打不开。
- **修法**：轻量应用服务器 →「防火墙」→ 添加规则：`TCP 443`，授权对象 `0.0.0.0/0`。
  （若走过渡模式，另加 `TCP 8080`。）

### P0-4 ICP 备案未通过 —— **已证实，不再是「未知」**

> **2026-11-14 23:20 实测结论：`trthirdworld.online` 未通过备案，正被阿里云拦截。**
> 这是域名打不开的**真正原因**，与代码、证书、SSH 都无关。

- **事实**：实例在**华北2（北京）**，属大陆机房。大陆机房用域名对外提供 Web 服务，
  未备案会被阿里云在网络层拦截。
- **实测证据（可复现）**：
  ```bash
  # 同一个 IP、同一个 80 端口，只换 Host 头，结果完全不同
  curl -s -o /dev/null -w '%{http_code}' http://47.95.117.212/                       # → 307  Server: nginx/1.31.4（Dify，正常）
  curl -s -H 'Host: trthirdworld.online' http://47.95.117.212/                        # → 403  Server: Beaver
  ```
  403 响应体是阿里云备案拦截页：
  ```html
  <title>Non-compliance ICP Filing</title>
  <script>window.onload=function(){document.getElementById("mainFrame").src=
    "http://www.aliyun.com/beian/beian-block?id=00000000006019558664";}</script>
  ```
- **DNS 侧完好**：`@` 与 `www` 在 `223.5.5.5` 和 `8.8.8.8` 上均返回 `47.95.117.212`。
  解析没问题，请求在**到达服务器之前**就被机房入口按 Host 拦掉了。
- **影响**：未备案 → 域名永远打不开，跟代码、跟证书都无关。这是**法律+网络双重阻断**。
  更麻烦的是连带效应：Caddy 申请 Let's Encrypt 证书时，HTTP-01 走 80 会被这个 403 挡，
  TLS-ALPN-01 走 443 同样过不了机房校验 → **证书也签不下来**。
  即「部署成功」会表现为「服务在跑、域名 403」，容易被误判成部署失败。
- **修法**：控制台 → 备案 → 查 `trthirdworld.online` 状态。
  - **已备案但不在这台服务器（接入备案未做）** → 做「接入备案」，最快 1–3 工作日。
  - **未备案** → 走阿里云备案（个人/企业，7–20 个工作日），需域名实名认证已完成。
  - **过渡**：先用 `http://47.95.117.212:8080/` 按 IP 验收（备案下来再切域名）。
    实测 IP 直访**不触发**备案校验，这条路确实可行。

### P0-5 今日 / 排课日期走 UTC，凌晨 0–8 点会错一天

- **位置**：`prototype/supabase-client.js:598`
  ```js
  return rpc("arc_daily_summary", { p_athlete: primary.id, p_date: null });
  ```
  `p_date: null` → 库端用 `current_date`，Postgres 在 Supabase 上是 **UTC**。
- **旁证**：`prototype/app.js:2600` 的注释已经承认过这个问题，并在排课那里绕开了：
  ```js
  // 传本地日期而不是 p_date=null：库里的 current_date 走 UTC，凌晨会排到"昨天"
  var today = new Date().toLocaleDateString("sv-SE");
  ```
  **但只绕开了排课，没绕开今日页/看板/周计划。**
- **影响**：北京时间 00:00–08:00，运动员打开「今日」，看到的是**昨天**的就绪度与建议；
  周计划可能落到上一周。对训练系统来说这是实质错误，不是显示问题。
- **修法**：客户端统一算本地日期并显式传参，三处 RPC 都改：
  ```js
  var TODAY = new Date().toLocaleDateString("sv-SE"); // YYYY-MM-DD，本地时区
  rpc("arc_daily_summary", { p_athlete: id, p_date: TODAY })
  rpc("arc_week_plan",     { p_athlete: id, p_any_date: TODAY })
  rpc("arc_assign_session",{ p_athlete: id, p_template: t, p_date: TODAY, p_note: null })
  ```
  并加一条回归：把 `TZ=Asia/Shanghai date -v+0H` 与 UTC 相差 8 小时时，`TODAY` 仍等于本地日期。

## 2. 数据与算法

### P1-1 登录失效（401）时，整屏降级成演示数据

- **位置**：`prototype/supabase-client.js:639-644`
  ```js
  if (e.status === 401 || /JWT|jwt/i.test(String(e.message||""))) {
    clearSession();
    S.mode = "demo"; S.stale = false; S.error = null;
    S.reason = "登录已失效，请重新登录";
    restoreDemo();          // ← 这里
  }
  ```
- **矛盾点**：上一轮 P0 刚把「刷新失败 → 换成演示数字」这条链路钉死（失败时保留 `lastGood`
  快照或显式报错，绝不 restoreDemo）。**401 这条分支是漏网的同款行为。**
- **影响**：token 过期（默认 1h）时，如果用户正停在某个页面，屏幕上的真数据会静默变成演示
  常量；注释里依赖「登录浮层盖住页面」，但浮层依赖渲染成功，一旦渲染出错就是真数据变假数据。
- **修法**：与失败分支对齐 —— 有 `lastGood` 就保留并标 `stale:"登录已失效，数据停在 X"`，
  没有就 `S.mode="error"`；无论如何**不 restoreDemo**。同时把「草稿丢失」降到最低：
  重新登录后自动重放最后一次未完成的写入。

### P1-2 ACWR(rolling) 分母口径不对（上一轮 P1，仍未修）

- 现在用「28 天窗口内**有训练的天数**」当分母，标准做法是**固定 28 天**（休息日按 0 负荷计入）。
  分母偏小 → rolling 偏高 → 对「练得不规律」的人误报风险。
- **修法**：`sum(load) / 28`，与 EWMA 侧的「休息日按 0 推进」保持同一口径；改完把
  `docs/` 里的口径说明同步改掉，并在 UI 指标卡的下钻里写明分母。

### P1-3 VBT 1RM 外推没有 R² 门槛（上一轮 P1，仍未修）

- `load-velocity` 回归只要有两个点就出 1RM，R²=0.1 也照给。**异常输入（1 个点、全同速度）**
  会得到荒谬的 1RM，且会被写进 `daily_metrics` 参与后续计算。
- **修法**：`R² < 0.80` 或 `点数 < 4` 或 `速度跨度 < 0.15 m/s` → 返回 null + 原因码，
  前端显示「—（样本不足/拟合差）」，不显示数字。

### P1-4 指标全量重算 O(n²)，同步有超时风险（上一轮 P1，仍未修）

- 每次写入触发全历史重算，数据到 2–3 年量级时单次同步可能超过浏览器/网关超时，
  表现为「排完课转圈很久然后失败」。
- **修法**：重算改成「从受影响日期起增量推进 N 天」（EWMA 是递推，天然可增量）；
  或改成队列异步 + 前端轮询状态。

### P2-1 图表在空数组上会算出 Infinity/NaN

- **位置**：`prototype/app.js:208` `const n = c.labels.length, gap = iw / n;`
  `n === 0` → `gap = Infinity` → 柱子 x 坐标 NaN → SVG 整块不渲染（白框）。
  同类：`svgGauge` 的 `W / c.items.length`。
- **影响**：目前调用方都保证非空，但只要出现「这一周一条数据都没有」，图形会白屏而不是空态。
- **修法**：入口 `if (!n) return emptyState(W,H,"本期没有数据");`，别让 NaN 流进路径。

### P2-2 图表尺寸在隐藏容器里会读成 0

- **位置**：`app.js:305` `Math.max(200, el.clientWidth || 360)`。
  元素在 `display:none` 时 `clientWidth === 0` → 回退成 360×200 的 viewBox；
  配合 `preserveAspectRatio="none"`，显示出来时会被**横向拉伸变形**（文字变胖）。
- **修法**：用 `ResizeObserver` 监听容器，尺寸变化才重绘；隐藏时不重绘，可见时补一次。

## 3. 交互逻辑与一致性

### P2-3 CSV 导出文件名用 UTC 日期

- **位置**：`app.js:2672` `new Date().toISOString().slice(0,10)`。凌晨 0–8 点导出，
  文件名会是「昨天」。数据没错，只是文件名，但会和「今日」页日期对不上，容易被当成两天的数据。
- **修法**：同 P0-5 用 `toLocaleDateString("sv-SE")`。

### P2-4 登录失效后没有「正在编辑的内容怎么办」的交代

- 排课/录入表单被 401 打断时，输入直接蒸发，没有任何提示。
- **修法**：表单值落 `sessionStorage` 草稿；401 后重登回到原表单并提示「已恢复你未提交的内容」。

### P2-5 深链进入受保护页时，先闪一下骨架再弹登录

- 未登录直接访问 `#/team/overview`，会先渲染骨架（因为 `S.syncing`），再因为无 session 弹登录。
- **修法**：`initFromURL` 里先判 `hasSession()`，无 session 直接进登录态，不渲染骨架。

## 4. 动画与状态同步

### P2-6 `resize` 没有节流，拖拽窗口会重挂全部图表

- **位置**：`app.js:2761`
  ```js
  window.addEventListener("resize", function () { fitStage(); requestAnimationFrame(mountCharts); });
  ```
  `mountCharts` 会对 `#content` 下**所有** `[data-chart]` 重建 `innerHTML`。
  拖动窗口一秒几十次 resize → 几十次全量重建 → 掉帧、滚动卡顿；且图表入场动画会被反复触发。
- **修法**：`ResizeObserver` + `requestAnimationFrame` 合并（已有 rAF，但缺「同一帧只跑一次」
  的标记和 150ms 去抖）；`mountCharts` 里对尺寸未变的 `el` 直接 `continue`。

### P2-7 骨架屏没有预留高度，内容到达时整页跳一下（CLS）

- `.sync-skeleton .skel-line` 只有 12px 高、10px 外边距，而真实卡片高度 120–200px。
  同步完成的瞬间页面整体上移，正在滚动/点击的人会点错位置。
- **修法**：骨架容器给 `min-height` 对齐真实卡片的典型高度；或把骨架做成与真实布局同构
  （同样的 grid 列数、同样的行高）。

### P3-1 `.live-dot` 无限脉冲动画在真库模式下仍有残留样式

- 真库模式已关掉仿真实时条，但 `.live-dot.on { animation: livePulse 2s infinite }` 仍会
  在个别标签上匹配到。属于「显示一个不存在的实时连接」的残留观感。
- **修法**：真库模式给根节点加 `.db-live`，CSS 里 `.db-live .live-dot.on { animation: none }`。
