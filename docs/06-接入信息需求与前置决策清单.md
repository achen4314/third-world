## 0. 怎么读这份清单

### 0.1 优先级定义

| 级别 | 含义 | 后果 |
|---|---|---|
| **P0** | 阻塞开工，无此项无法写代码或无法验证 | 对应模块完全停摆 |
| **P1** | 阻塞上线，可先开发但不可对外 | 国内应用商店 / 监管过不去 |
| **P2** | 可延后，不阻塞首版 | 影响规模化与体验 |

### 0.2 提交方式与安全红线

**不要在本对话中粘贴真实密钥。** 理由：对话内容会进入模型上下文，密钥一旦进入即视为泄露，必须轮换。正确做法：

| 类型 | 提交渠道 |
|---|---|
| 密钥类（`service_role`、DB 密码、OAuth secret） | 写入本地 `.env`（我已确保 `.gitignore` 覆盖），或你自建密钥管理；我只读取所需键名 |
| 决策类（选型、主体、范围） | 直接对话回答即可，无敏感性 |
| 材料类（执照、备案号） | 只给**编号与要素**（如统一社会信用代码前 6 位、备案号），**不要发扫描件原图** |
| 账号类（厂商开发者账号） | 只需告知「已注册 / 未注册 / 卡在审核」，凭据走 OAuth 后台授权，不必给我密码 |

### 0.3 一句话结论（先看这个）

| 缺口 | 真正卡点 | 你能最快解除的动作 |
|---|---|---|
| A 认证与 RBAC | 身份来源未定 | 回答 D4 一个问题即可开工 |
| B 数据库与 RLS | 库归属未定 | 回答 D2，我可先用本地 Postgres 跑通全部迁移与越权测试 |
| C Supabase 凭据 | 无任何接入证据 | 给 Project URL + 两个 key + 连接串（走 `.env`） |
| D 设备授权 | 厂商账号与商务流程，周期最长 | 先走「免授权通道」（FIT/CSV 导入 + BLE 直连），我可立即开工 |

| F 隐私同意与导出删除 | 敏感个人信息范围未定 | 回答 D6，我可先建 consent 模型与端点 |

### 1.2 我可先搭（不阻塞）

- 双令牌认证：access（短时效、内存持有）+ refresh（服务端表存储、可吊销、轮换检测）。
- RBAC 中间件：权限矩阵**配置化**（`permissions.yaml`），改矩阵不改代码；默认填现有 7×26。
- `scope` 解析器：把「当前用户的可见范围」解析成 SQL 条件，供仓储层统一注入 —— 这是与 RLS 对齐的关键。

### 5.2 时间与顺序（不可压缩的部分）

### 6.2 数据出境门槛（F4 选「境外」时必读）

按《促进和规范数据跨境流动规定》（2024-03-22 施行），非关键信息基础设施运营者：

| 当年累计向境外提供 | 义务 |
|---|---|
| 不满 10 万人**非敏感**个人信息 | **免于**申报安全评估、订立标准合同、认证 |
| 10 万–100 万人非敏感，或 **不满 1 万人敏感** | 须订立**个人信息出境标准合同**或通过**保护认证** |
| 100 万人以上非敏感，或 **1 万人以上敏感** | 须申报**数据出境安全评估**（有效期 3 年） |

**对本项目的含义**：训练 App 的 HRV / 睡眠 / 月经周期属敏感个人信息，**1 万人是很低的门槛**。若用境外 Supabase 且用户量过万，就要走标准合同或安全评估。加上 ICP 备案要求境内服务器 —— **「境内主库 + 境外仅非个人信息」是最省事的形态，但这需要你拍 D3。**

> 以上为公开规定要点整理，具体适用请以现行法规与专业法律意见为准，我不提供法律结论。
