## 1. P0 — 必须修完才能上线

### P0-1　界面挂「真实数据」但数值还是演示常量

- **位置**：`prototype/supabase-client.js:290`（`S.mode = "live"` 在 `await load()` 之前）→ `apply()` 才真正替换数组（`:904`）。
- **现象**：登录成功后、数据落地前的那段窗口里，顶栏是「真实数据 · RLS 生效」，页面数值是 `data.js` 的演示常量。**本次已在浏览器复现并截图**（登录后首屏 ACWR 1.04 / RMSSD 64 / TM 1.51，而库里是 0.87 / 64 / —）。
- **影响**：用户无法区分「这是我今天的就绪度」还是「这是示例」。这是整套产品唯一的诚信底线，也是最容易被当成"演示品"的理由。
- **修法**：引入 `S.syncing`。`mode` 只允许在 `apply()` 内切到 `live`；`syncing` 为真时页面渲染骨架 + 标签写「同步中」，**不渲染任何数值**。

### P0-2　任何一处映射异常 → 整个库回退成演示数据

- **位置**：`supabase-client.js:509–520`（`catch` → `restoreDemo()`）。
- **现象**：本次真实环境就踩到了——`jump_tests` 在真库是 to-one（对象），mock 里是数组，`(s.jump_tests||[]).forEach` 抛错 → 整页回退演示数据。当时页面看起来一切正常，只是数字全是假的。
- **影响**：一个字段形状变化（升级 PostgREST、加一列、改关系）就能让全站静默变成假数据。
- **修法**：`apply()` 内部按数据集分块 try/catch。失败的那一块置空并计入 `S.partial`，其余照常生效；只有「会话失效」和「连不上库」才允许整体回退。

### P0-3　休息日不衰减，停训两周仍然显示「可执行既定强度」

- **位置**：`migrations/20261114000011_state_vs_daily.sql:105–114`（休息日分支只延续、不推进 EWMA）。
- **现象**：`ctl/atl/acu/chr` 只在有训练的日子更新。连续休息时 ATL 保持在停训前水平，TSB 永远不为正，ACWR 恒等于停训前的值 → 就绪度继续给「可执行既定强度」。
- **影响**：这是**会直接导致错误训练决策**的模型错误。休息 10 天和休息 1 天在界面上没有区别。
- **修法**：休息日按 0 负荷推进 EWMA（`ctl := ctl + (0 - ctl)/42`，ALT 同理，acu/chr 同理），把「延续」限制在 `tsb` 的显示口径上。注意：这不违反「缺测不补 0」——那条只针对 `tl.srpe` / `load.week` 这类日聚合量。

### P0-4　长历史/多队员时数据被静默截断

- **位置**：`supabase-client.js:385`（`daily_metrics` `limit: "8000"`）、`:381`（activities `limit 200`）、`:389`（test_sessions `limit 100`）。
- **事实**：PostgREST 单次返回上限默认 **1000 行**（Dashboard → API → Max Rows）。写 `limit=8000` 不会生效。`daily_metrics` 每人每天最多 18 行，即 **单人约 55 天就撞顶**；教练看 5 名队员时不到 2 周就撞顶。
- **影响**：趋势线、ACWR、累计次数会在无任何提示的情况下变成「部分数据算出来的结果」。目前只有 14 天数据，所以没暴露。
- **修法**（二选一，建议都要）：
  1. 查询按 `athlete_id` 过滤 + 只取最近 90 天（`metric_date=gte.`），并显式带上 `Prefer: count=exact` 校验行数；
  2. 「累计/总数」类指标改走 RPC（服务端 `count(*)`），不要用前端数组长度。

## 2. P1 — 首批真实用户就会撞到

### P1-1　合规承诺没有入口（导出 / 删除）

- **位置**：`migrations/…0008_calculations.sql` 里的 `arc_export_my_data()` / `arc_delete_my_account()` / `arc_delete_activity()` 都已实现并授权，但 `prototype/` 里 **没有任何调用**（`grep arc_export_my_data prototype/` 为空）。
- **影响**：隐私政策与「档案与设置」页都写着「可随时导出或删除」。现在用户做不到，只能找运营用 SQL 处理。这在应用商店审核与个人信息保护合规上都是硬伤。
- **修法**：`data/profile` 加「导出我的数据（JSON 下载）」「注销账号（二次确认 + 输入邮箱）」；单次训练详情页加「删除这条记录」。三个 RPC 都已就绪，纯 UI 工作。

### P1-2　ACWR(rolling) 分子分母单位不一致

- **位置**：`…0011:118`：`(v_w7sum / 7.0) / (v_w28sum / v_w28n)`。
- **问题**：`w7sum`/`w28sum` 是 `sum(training_load)`，`w7n`/`w28n` 是 **`count(*)` 即训练条数**（不是天数）。所以
  - 分子 = 每**日历天**平均负荷；
  - 分母 = 每**次训练**平均负荷。
  一天一练时两者近似相等，误差被掩盖；**一天两练时 `w28n` 翻倍 → 分母减半 → ACWR 虚高约 2 倍**，会直接被规则读成「负荷急增」。
- **附带**：`v_w7n = 7` 要求 7 天内凑够 7 条记录，`v_w28n >= 26` 要求 28 天内 26 条——对一天一练者是「全勤」，对多数用户永远不满足，于是该指标长期显示「—」，等于事实废弃。
- **修法**：分母改为 `v_w28sum / 28.0`（口径与文档一致）；有效性门槛改为「窗口内有记录的天数 ≥ 14」，并在返回值里带 `valid_days`，页面显示「基于 16/28 天」。

### P1-3　VBT 1RM 外推没有 R² 门槛，也没有外推距离告警

- **位置**：`…0008:139`（`n >= 3` 且 `slope < 0` 即返回 `ok:true`）。
- **问题**：三个点也能拟合出 R²=0.4 的线，1RM 会被当真值展示。规则页写的是「R² ≥ 0.95 才出 1RM」，代码里并没有这个门槛。
- **修法**：`r2 < (rules.payload.vbt.r2_min ?? 0.90)` 时返回 `ok:false` + `reason`；`load_1rm > load_max × 1.3` 时附 `extrapolated_far: true` 并在 UI 标「外推过远」。

### P1-4　指标重算是「每次写入全量重跑」

- **位置**：`…0011:74` 起：`for d in generate_series(v_start, v_to)`，循环内 4 条查询。
- **量级**：14 天实测 <10 ms（可忽略）；1 年数据 ≈ 365 × 4 = 1460 条查询/次写入；批量导入 100 条 → 100 次全量重算（O(n²)）。
- **影响**：现在无感，导入功能一上就会超时（PostgREST 默认 statement timeout 8s）。
- **修法**：批量导入时 `alter table ... disable trigger`，导入后调一次 `arc_recompute_metrics`；或改为从「最后一条已算日期 − 1」增量推进。

### P1-5　「忘记密码」是死路

- **位置**：登录浮层「忘记密码」→ `POST /auth/v1/recover`。当前未配 SMTP，接口返回 500（本次实测 `Unable to process request`），用户只会看到失败。
- **修法**：短期在按钮旁明确写「暂未开通邮件找回，请联系管理员重置」（管理员侧已有 `npm run accounts` 可重置密码）；正式修需配 SMTP（`docs/10` 第 3 项）。

## 4. P3

- **P3-1** 就绪度负荷分量：`acwr < low` 时最低给 60 分。低训练量人群 ACWR 天然偏低，会被读成「状态还不错」。建议加「7 日负荷 < 目标 50%」时的附加提示。
- **P3-2** `arc_vbt_profile(jsonb)` 未校验调用者能否读该 session（`security definer` 直读 `vbt_sets`）。UUID 难猜，但属于跨租户可读面。建议加 `arc_can_read_scope` 同款校验。
- **P3-3** 图表首帧在 `requestAnimationFrame` 测量 `clientWidth`，字体未就绪时可能拿到 0 → 回退 360 宽，首帧线宽/字号偏差。

## 5. 本次审查确认「已经是对的」（不用再动）

- **时区**：`arc_local_today()` 已把 `current_date`(UTC) 换成组织时区今天；触发器传 `null` 走 `max(本地今天, 最晚训练日)`，补录历史会带动后续派生值。
- **缺测不补 0**：`tl.srpe`/`load.week` 只在有训练的日子写；状态量与日聚合量已分开（0011）。
