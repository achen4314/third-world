# 界面可用性审查与优化方案 · 2026-11-16

> 基于逐行读 `prototype/app.js` / `data.js` 的渲染与导航代码，不依赖主观观感。
> 每条给出：现象 → 代码证据 → 影响 → 方案 → 理由。本次**不改代码**，只出可执行清单。

## 总体判断

产品的信息是**全的**，问题在于「同一层级塞了太多优先级相同的信息」：
顶栏 11 个控件、页面 4 层页头、指标卡 4 行文字、同一状态说三遍。
用户每次操作的成本都花在「分辨哪个是结论、哪个是操作、哪个只是元信息」上。

根因有三条：
1. **设计文档语言下沉进了 UI**（"本模块只输出 TL 与 ACWR""边界说明"）。
2. **元信息默认全展示**（每个数值都挂着 metric_id / 窗口 / 来源 / 口径串）。
3. **同一动作/状态有多个入口**（记录训练 3 处、同步状态 3 处、VBT 两处导航）。

## A. 信息层级

### A1 顶栏控件过载（P0）
- **现象**：一行里挤进返回、面包屑、角色、实时 1 Hz、即时刷新、对标评分、28 日/EWMA、＋记录训练、同步状态、工作台、⌘K 共 11 个控件。
- **证据**：`app.js:2268-2291`。
- **影响**：唯一的高频主操作「＋记录训练」被状态类控件包围；状态 pill 与页内 chip 内容重复。
- **方案**：顶栏只留 3 个固定位：①返回/标题 ②主操作「＋记录训练」 ③状态点（点击展开诊断）。窗口、口径、对标评分、角色、⌘K 移入页内 chip 行或二级菜单。
- **理由**：Fitts 定律 + 认知负荷——主操作应唯一且位置恒定；同一状态在一个视图里只出现一次。

### A2 一个页面四层页头（P0）
- **现象**：`page-head`（eyebrow / h1 / question / chips / actions）下面紧跟 `hero`（kicker / 大标题 / 长导语 / 3 条证据 / 2 个按钮），随后每个卡片还有自己的 section-title。
- **证据**：`app.js:2392-2398`、`app.js:412-427`；`today` 页同时有 question「今天该练什么」和 hero 结论「就绪度 XX」（`app.js:703-724`）。
- **影响**：一页出现两个"标题"和两组按钮，用户不知道哪个是结论、该点哪里。
- **方案**：合并成一层——eyebrow 只放数据来源；h1 唯一，直接写结论（如"就绪度 72 · 可执行既定强度"）；question 降为副标题或删除；页面级 actions 与 hero actions 合并，总数 ≤2。
- **理由**：单一视觉焦点；标题层级必须唯一，否则结论被稀释。

### A3 指标卡信息密度过高（P1）
- **现象**：每张卡 4 行——label / value+unit / delta / chips(metric_id·窗口·来源)；delta 常是口径串「急性/慢性负荷比 · EWMA(7/28)」。
- **证据**：`app.js:374-381`、`trio()` 调用；`app.js:728`。
- **影响**：用户真正要看的只是 value，其余 3 行是元信息；mac 三列布局下形成大面积扫描噪音。
- **方案**：卡内只留 label + value + 一行人话短说明；口径/来源/窗口收进已有下钻浮层（drill 机制已存在），数值旁放极小的"i"表示可下钻。
- **理由**：渐进披露——元信息按需查看，不默认占用视觉带宽。

### A4 说明性 note 卡片堆积（P2）
- **现象**：页面底部常驻「今日页边界」「本模块只输出 TL 与 ACWR」等解释自身设计的文案。
- **证据**：`app.js:739-740`、`app.js:771-773`、多处 `S_note`。
- **影响**：这是设计文档语言，不是给运动员/教练的操作信息，却占据首屏位置。
- **方案**：移入"？"帮助浮层或首次使用引导；页内只保留与当前决策直接相关的提示（缺测、过期、数值越界）。
- **理由**：区分「产品说明」与「任务信息」，后者才配出现在工作区。

## B. 布局与导航

### B1 导航概念交叉重复（P1）
- **现象**：`分析` 组有「VBT 分析」「跳跃表现」，`测试` 组有「VBT 采集」「跳跃采集」——同一概念两处入口。
- **证据**：`data.js:214-222`。
- **影响**：用户找"我的跳跃成绩"要在两个组里试错；边界只能靠 `今日页边界` 的文字补救，说明导航本身没讲清。
- **方案**：按用户动作归组——训练（计划/记录/方案库）、测量（采集与原始记录）、分析（趋势/对比/报告）。VBT 与跳跃只在「测量」保留采集入口，结果在分析页以卡片呈现，不再建同名导航项。
- **理由**：一个概念一个入口；导航按「我要做什么」命名，而非按数据产出方命名。

### B2 iPhone 双层导航常驻（P2）
- **现象**：底部 tabbar（5 项）之上还有横向 subnav（概览 + 6 个子项）。
- **证据**：`app.js:2294-2301`。
- **影响**：小屏上两级导航同时占高，内容区被压缩。
- **方案**：iPhone 只保留底部 tabbar；子项改为页面内分段控件或「全部」入口按需展开。
- **理由**：小屏每一像素都应让给内容；二级导航按需出现。

### B3 演示占位在真库模式仍会注入（P1）
- **现象**：未连库时给 20+ 路由注入 livebar、对标评分、数据融合；登录真库后这些整块消失，界面"变样"。
- **证据**：`app.js:2370-2391` 的 `LV` 分支与 `scoreMap`。
- **影响**：演示态与真实态视觉差异大，削弱信任；且占位可能被误读为真数据。
- **方案**：演示占位默认关闭，只在显式「演示模式」开关下出现；真库模式永不显示 1 Hz 与对标评分。
- **理由**：保持两种模式的信息架构一致，避免"登录后界面换了"。

## C. 操作效率

### C1 「记录训练」三处入口（P0）
- **现象**：顶栏「＋ 记录训练」、今日页卡片「记录今天的训练」、训练模块入口都能触发录入。
- **证据**：`app.js:2288`（`data-act="arc-record"`）、`app.js:733`、`train` 模块。
- **影响**：路径不一致，用户记过一次后不确定下次从哪进。
- **方案**：全局唯一主按钮＝顶栏「＋记录训练」；今日页与训练页的卡片改为「查看训练记录」类导航，不再触发录入浮层。
- **理由**：一致性与可预测性；高频动作固定位置能形成肌肉记忆。

### C2 缺测/不可计算文案术语化（P1）
- **现象**：「不可计算 · 窗口有效天数不足」「28 日窗口内有效天不足 26 天」。
- **证据**：`app.js:1084`、`app.js:1798`。
- **影响**：用户看到"有效天数"却不知道自己该做什么。
- **方案**：统一为可点击短句「数据不足 · 看还缺什么」，浮层内列出具体缺口与补录入口。
- **理由**：错误提示必须给出下一步动作，而不只是解释原因。

### C3 状态提示三处重复（P2）
- **现象**：顶栏同步 pill、页内 `dataChip()`、页首 `S_note` 横幅同时说"数据过期/失败"。
- **证据**：`app.js:2281-2289`、`app.js:630-647`、`app.js:2360-2369`。
- **影响**：同一条信息说三遍，挤占本就紧张的顶部空间。
- **方案**：只保留页首横幅（最重要）；顶栏缩成一个状态点；页内 chip 只留口径/窗口类，不再重复状态。
- **理由**：一条信息一个位置；告警重复反而降低警觉。

## 优化优先级

| 批次 | 条目 | 预期收益 |
|---|---|---|
| P0（每屏都遇） | A1 顶栏、A2 页头、C1 唯一录入口 | 立刻降低"找不着北"感，主操作恒定 |
| P1（高频使用） | B1 导航去重、A3 指标卡、B3 演示占位、C2 缺测文案 | 信息层级清晰，操作有下一步 |
| P2（打磨） | A4 说明卡、B2 手机导航、C3 状态去重 | 释放首屏空间，三端一致 |

## 需要你拍板的三处取舍

1. **导航重组（B1）会改动路由**。若必须保留现有路由，只能做视觉合并（把 VBT 分析与采集放在同一页的两个标签），效果打折但风险低。你选哪种？
2. **演示占位是否默认关闭（B3）**。关闭后评审演示会少掉"实时推流/对标评分"的观感，但真库体验更干净。是否保留一个可见开关？
3. **指标卡下钻（A3）是否接受"默认不显示口径串"**。这会让"严谨性"的可见度下降——口径仍在，但要点一下才看到。是否接受？

确认后我按批次落地，每批改完跑 `verify:modules` + 三端构建，确认无回归再进入下一批。

## 执行记录（2026-11-16）

### P0 · 界面收敛（commit `bf35656`）

- **A1**：顶栏从 11 个控件收敛为三个固定位——返回/标题、唯一主操作「＋ 记录训练」、状态点；窗口、口径、对标评分、角色、⌘K、工作台下沉到页首 chip 行与「工具与口径」浮层。新增 `statusInfo()` / `demoMode()` / `toolChips()`。
- **A2**：首个 hero 的 kicker/title/lead/actions 上提到唯一页头；actions 合并去重后最多两个；hero 渲染为 `lifted` 时只保留证据条，不再重复标题与按钮。页头 h1 现在直接是结论（如「就绪度 72 · 可执行既定强度」）。
- **C1**：今日页「记录今天的训练」改为「查看训练记录」（导航到 `train/calendar`）；训练页主操作改为查看类；方案库「开始搭配训练」按钮移除、文案指向顶栏唯一入口。
- 新增 `.status-dot` / `.primary-cta` 样式。

### P1 · 信息层级（commit `b75c202`）

- **B1**：导航按动作重组为 训练 / 测量 / 分析。`lab/*` 全量改路由为 `measure/*`（48 处）；`analyze` 下 VBT 分析与跳跃表现不再建导航项，结果仍以卡片保留在分析概览页。权限矩阵与边界说明同步改名。
- **A3**：指标卡只留 label + value + 一行短说明；metric_id / 窗口 / 来源收进数值旁的极小 `i` 下钻到既有口径浮层。删除不再使用的 `trio()`。
- **B3**：`state.demoFx = false`，1 Hz 假流 / 对标评分 / 融合示意默认不注入；真库模式无论开关如何都不注入。开关放在「工具与口径」浮层。审计脚本显式打开开关后再测演示机制。
- **C2**：`na` 指标的术语式 delta 改为可点短句「数据不足 · 看还缺什么」，新增 `gap` 浮层按 metric_id 列出缺口与补录入口；不补 0、不估算、不跨来源合并。

### P2 · 打磨（commit `3551c54`）

- **A4**：移除 6 处页尾「边界说明」常驻卡，收进「工具与口径 → 模块边界与说明」浮层，内容取 `A.BOUNDARIES`。
- **B2**：iPhone 隐藏常驻 subnav，页首增加「子页」入口，按需展开当前分组的二级页面列表。
- **C3**：`dataChip()` 不再重复同步状态，只保留口径/窗口类信息；状态只由顶栏状态点与异常横幅各说一次。
